# ZANDELA / LIVING SYSTEM

**A governed, evidence-backed system for building, validating, and presenting evolving technical work.**

ZANDELA / LIVING SYSTEM is not a conventional portfolio. It is a public-facing projection of a governed technical body of work: projects, evidence, capabilities, decisions, failures, corrections, and current state are treated as structured institutional records rather than loose marketing claims.

The governing thesis is simple:

> **Build systems that make humans and institutions more capable.**

## What this repository is

This repository is the **public showcase layer** for ZANDELA / LIVING SYSTEM.

It contains sanitized architecture, selected build notes, public-safe evidence, and demonstration material derived from a separate private canonical repository.

It does **not** contain:
- credentials or secrets;
- private customer or case data;
- internal prompts or agent traces;
- sensitive evidence;
- unpublished canonical records;
- proprietary implementation details that are not intended for public release.

The public repository is a projection, not the source of truth.

## Core operating model

```text
candidate → validated → ratified → canonical → public projection
```

AI and automation can propose, inspect, compare, validate, and help execute work. They do not silently redefine canonical state.

The system preserves a strict distinction between observation, inference, assertion, verification, authority, publication state, and maturity.

A concept is not a prototype. A prototype is not production. A passing test proves only the property that was tested.

## Architecture at a glance

```text
Private canonical repository
        ↓
Deterministic validation
        ↓
Human ratification
        ↓
Runtime/public-safe projection
        ↓
ZANDELA / LIVING SYSTEM
```

Key principles:
- Constitution before implementation
- Canonical state separate from presentation
- Typed and versioned entities
- Provenance and supersession
- Human authority for consequential state changes
- Fail-closed publication boundaries
- Bounded parallel agent execution
- Independent review before material promotion
- Human-readable + machine-readable engineering evidence

## Engineering credibility

Material engineering changes use a two-layer commit standard:

**Human-readable subject**
```text
G6-REM001: Prevent worker authority expansion outside authorized paths
```

**Machine-readable trailers**
```text
Event-Type: SECURITY_REMEDIATION
System: zandela-living-system
Gate: G6
Pass: REM001
Status: READY_FOR_INDEPENDENT_REVIEW
Tests: PASS
Critical-High-Open: 0
Human-Authority-Preserved: true
Next-Gate: HUMAN_RATIFICATION
```

For material work:
- **Commit** = durable engineering evidence
- **Checkpoint** = canonical institutional promotion record
- **Build note** = understandable credibility narrative
- **Public post** = sanitized publication-safe lesson

## Why this exists

Modern AI systems can increase execution speed dramatically, but speed without authority boundaries creates a new class of failure: systems can become difficult to trust precisely because they are easy to change.

ZANDELA explores the opposite model:

**increase intelligence and execution capacity without increasing uncontrolled authority.**
